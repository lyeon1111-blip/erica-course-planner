# 수강신청 전 한 화면

한양대 ERICA 학생을 위한 **졸업요건 진단 + 다음 학기 강좌 추천** 서비스.
데이터 애널리스틱 수업 팀 프로젝트.

시연은 광고홍보학과 데이터만 들어 있다. 설정에서 학과·학번·학년을 고르고
"예시 이수내역 불러오기"를 누르면 나머지 화면이 열린다.

**추천 화면은 아직 비어 있다.** 쿼리를 짜는 중이고, 화면은 그 다음에 붙인다.

## 왜 만들었나

수강신청이 끝나면 헤이영 하나로 충분하다. 문제는 그 전이다.

| | 수강신청 전 | 수강신청 후 |
| --- | --- | --- |
| 지금 | 에타 ⇄ 헤이영 ⇄ 에타 ⇄ … | 헤이영 |
| 이유 | 에타는 내가 뭘 채웠는지 모르고, 헤이영은 이번 학기에 뭐가 열리는지 모른다 | 시간표·출석·성적·졸업사정이 한곳에 |

헤이영을 대체하는 앱이 아니라, **신청 전 구간을 한 화면으로 합치는 도구**다.

## 데이터에서 나온 것

두 학기(2026-1, 2026-2)를 모아 놓으니 추천의 근거가 생겼다.

- **광고홍보 전공 37과목이 1학기 19 / 2학기 18로 갈리고, 양쪽에 다 열리는 과목은 0개다.**
  한 번 놓치면 최소 1년을 기다린다. 학기를 건너뛰고 보여 줄 이유.
- **이름으로 추정한 선후수 8쌍이 전부 1학기 → 2학기 순서와 맞았다.**
  (데이터애널리틱스 → 심화데이터애널리틱스 등) "계열 이어 듣기" 추천의 근거.
- **설득커뮤니케이션은 전공핵심 · 영어전용 · IC-PBL 세 요건을 한 번에 채운다.**
  "졸업 최단" 추천의 근거.
- **같은 과목 안 경쟁 차이는 시간보다 교수님 차이다.** 같은 교수님 분반끼리는 평균 7%p,
  교수님이 다르면 평균 22%p 차이 난다. (설득커뮤니케이션 이현우 160% · 최태랑 83%)
- 전공심화끼리 시간이 겹치는 건 한 학기 안에서 **2쌍**, 둘 다 1학기다.

## 추천 (화면 완성, 로직은 R로 작업 중)

희망 직무를 고르면 **남은 학기 동안 들을 수 있는 그 분야 수업**을 학기별로 보여 준다.
학생에게는 직무 이름으로 보이고, 묶음은 학과 교육과정표의 카테고리 분류를 따른다.

| 화면에 보이는 이름 | 교육과정표 분류 |
| --- | --- |
| 광고기획자(AE)·브랜드 매니저 | 기획 |
| 데이터 분석가·마케팅 애널리스트 | 인사이트 및 데이터 |
| 디지털 마케터·미디어 플래너 | 퍼포먼스 및 미디어 |
| 크리에이티브·콘텐츠 제작 | 크리에이티브 및 콘텐츠 |
| 홍보(PR)·공공 커뮤니케이션 | PR |
| 창업·신사업 기획 | 창업 |

규칙: 분야 과목 × 실제로 열린 학기(2026년 기준) × 이미 들은 과목 제외.
화면은 `data/rec_sample.csv`와 같은 모양의 R 결과를 그대로 그린다.

| 열 | 뜻 |
| --- | --- |
| track | plan · data · media · crea · pr · startup |
| 학기 | 2026-2 · 2027-1 · 2027-2 |
| 학년학기 | 3-2 · 4-1 · 4-2 |
| 학수번호 | 조인 키 (이름은 바뀔 수 있음) |
| 개설 | 확정(이번 학기 열림) · 예상(올해 같은 학기에 열렸음) · 미정(올해 안 열림) |
| 이유 | 화면에 그대로 나가는 한 줄 (없으면 빈칸) |

교육과정표와 실제 개설이 어긋나는 것: 교육과정표 53과목 중 **8과목은 2026년에 안 열렸고**,
광고원론·스타트업비지니스프랙티컴은 표와 **다른 학기**에 열렸다. 여론과트렌드 → 여론과정치커뮤니케이션처럼
**이름이 바뀐 과목**도 있어서 학수번호로 묶는다.

## 구성

```
index.html          발표 자료 (build.py로 생성)
present.html        발표 자료 원본 조각
demo/index.html     시연용 시안 — 설정·진단·시간표·추천·인기 수업
data/rec_sample.csv 추천 결과 예시 (R 결과가 맞춰야 할 모양)
app/index.html      초기 프로토타입
app/tess/           글자 인식용 언어 데이터 (kor · eng)
build.py            present.html → index.html 빌드
```

초기 프로토타입은 시간표 캡처를 읽기 위해 [Tesseract.js](https://tesseract.projectnaptha.com/)를
쓴다. 언어 데이터는 `app/tess/`에 같이 두고 브라우저 저장소에 넣어 쓰므로,
글자 인식 과정에서 **이미지가 바깥으로 나가지 않는다.**
(확장자가 `.wasm`인 것은 이전 배포 환경이 `.gz`를 내주지 않아 바꾼 것으로,
내용은 gzip으로 묶인 traineddata다.)

## 데이터 수집

- 한양대 ERICA 수강편람 2026-1 · 2026-2 — **972개 강좌 / 455개 과목**
  (1학기 508강좌 · 348과목, 2학기 464강좌 · 337과목)
- 이수제한 문구 **338건** 파싱 (`학과 × 학년` 표)
- 졸업요건 규칙 **4개 학과 × 2개 학번**
- 수집: 2026년 11월 16~17일

학수번호가 조인 키다. 수업번호는 학기마다 다시 매겨지므로 학기를 건너뛰어
붙이면 안 된다.

포털이 `robots.txt`로 자동 수집을 막아 두기 때문에 **크롤러를 쓰지 않았다.**
사람이 조회한 결과를 붙여넣으면 Google Apps Script 도구가 정리해 쌓는 방식으로 모았다.

## 개인정보

성적과 이수내역은 **브라우저 안에서만** 처리한다. 서버로 보내지 않는다.
강의평은 에타에서 가져오지 않고 여기서 새로 쌓는다.

## 로컬에서 보기

```bash
python3 -m http.server 8000
# http://localhost:8000
```

## 발표 자료 수정

`present.html`은 아티팩트용 조각이라 `<head>`가 없다. 빌드하면 단독 페이지가 된다.

```bash
python3 build.py present.html index.html
```
